1편에서 잡은 토폴로지대로, 이 편에서는 Bastion과 마스터·워커의 네트워크를 고정한다. Bastion은 사외망 쪽 ens33(192.168.34.226/24)과 사설망 쪽 ens34(172.31.1.1/24)를 함께 갖고, 마스터와 워커는 사설망 ens34만 둔다. 노드의 기본 게이트웨이는 Bastion의 172.31.1.1이므로, Bastion에서 IP 포워딩과 NAT를 열어야 노드가 외부와 통신할 수 있다. 설정이 끝나면 호스트 이름과 /etc/hosts를 맞추고, 3편에서 쓸 hardway/certs 디렉터리를 만든다.

터미널 구성

Bastion에서 root로 SSH할 수 있게 sshd_config에 PermitRootLogin yes와 PasswordAuthentication yes를 넣고 sshd를 재시작한다. 랩에서 접속과 자동화를 편하게 하려고 연 설정이다. 운영 환경에서는 키 인증을 쓰고 root 로그인은 끄는 편이 맞다.

이어서 기본 패키지를 설치한다. openssl은 3편에서 인증서를 만들 때 쓰고, net-tools는 아래에서 ifconfig를 볼 때 쓴다. ipset은 이후 9편에서 kube-proxy(IPVS)를 구성할 때도 설치한다.

# Root 계정으로 바로 사용
sudo passwd root
sudo vi /etc/ssh/sshd_config

# config 파일에 아래 내용 추가
PermitRootLogin yes
PasswordAuthentication yes

# SSH 서비스 재시작
sudo systemctl restart sshd

# Bastion 서버 구성
apt update -y;\
apt upgrade -y;\
apt install net-tools htop vim openssl ipset python3-pip -y;\
pip install scp paramiko

Bastion 서버 구성 ( Ubuntu NetPlan으로 고정 IP 설정하기 )

Bastion의 Netplan에서 인터페이스 역할을 나눈다. ens33은 1편에서 사외망으로 둔 쪽이고, 주소는 192.168.34.226/24, 게이트웨이는 192.168.34.1, DNS는 8.8.8.8이다. ens34는 사설망 172.31.1.1/24이고, 이쪽에는 기본 게이트웨이를 두지 않는다. 적용 전에 원본 YAML을 백업한 뒤 netplan apply로 반영한다.

root@bastion:# cd /etc/netplan

# 원본 백업
root@bastion:# cp 00-installer-config.yaml 00-installer-config.yaml.bak

# Ubuntu NetPlan으로 고정 IP 설정하기
root@bastion:# vi 00-installer-config.yaml

root@bastion:/etc/netplan# cat 00-installer-config.yaml
---
# This is the network config written by 'subiquity'
network:
  version: 2 
  ethernets:
    ens33:
      addresses:
      - 192.168.34.226/24
      gateway4: 192.168.34.1
      nameservers:
        addresses:
        - 8.8.8.8
        search: []
    ens34:
      addresses:
      - 172.31.1.1/24
      nameservers:
        addresses:
        - 8.8.8.8
---

# IP 변경 적용 후 확인
root@bastion:/etc/netplan# sudo netplan apply

root@bastion:# apt -y update 
root@bastion:# apt install -y net-tools
root@bastion:# systemctl status sshd
root@bastion:# apt-get install -y wget curl vim openssl

root@bastion:# telnet www.google.com 80
root@bastion:# sudo ufw disable
Firewall stopped and disabled on system startup

root@sj-bastion:# telnet www.google.com 80
Trying 203.0.113.50...
Connected to www.google.com.
Escape character is '^]'.

root@bastion:# ping 8.8.8.8

# IP 포워딩 활성화
sudo sysctl -w net.ipv4.ip_forward=1

# 영구 설정 
sudo vi /etc/sysctl.conf
---
net.ipv4.ip_forward = 1   # 항목 추가

# 변경 사항 적용
sudo sysctl -p

# iptables 를 활용한 NAT 규칙 추가
- ens33: 외부와 연결된 인터페이스 (외부 통신)
- ens34: 172.31.1.1/24: 내부 네트워크 대역

# 사설 대역(ens34) 172.31.1.0/24 NAT 규칙 추가 ( ens33에 대해서 사설대역(ens34)을 마스커레이드 )
sudo iptables -t nat -A POSTROUTING -s 172.31.1.0/24 -o ens33 -j MASQUERADE

# 규칙 조회
root@sj-bastion:# iptables -t nat -L --line-numbers
Chain PREROUTING (policy ACCEPT)
num  target     prot opt source               destination         

Chain INPUT (policy ACCEPT)
num  target     prot opt source               destination         

Chain OUTPUT (policy ACCEPT)
num  target     prot opt source               destination         

Chain POSTROUTING (policy ACCEPT)
num  target     prot opt source               destination         
1    MASQUERADE  all  --  172.31.1.0/24        anywhere            
2    MASQUERADE  all  --  10.20.0.0/24         anywhere            
3    MASQUERADE  all  --  anywhere             anywhere 
        
# 동작 요약 
# 내부 네트워크의 IP 주소를 외부 네트워크로 변환:
# 내부 네트워크(172.31.1.0/24)에서 출발하는 모든 패킷이 외부 네트워크로 나갈 때, ens33의 IP 주소를 사용하도록 출발지 IP를 변환합니다.

# IP 마스커레이드의 목적:
# 하나의 공인 IP 주소(또는 외부 네트워크의 인터페이스 IP 주소)를 사용하여 내부의 여러 프라이빗 IP 주소를 NAT 처리할 수 있습니다.
# 이는 내부 네트워크에서 외부로 데이터를 전송할 때 주로 사용됩니다.

# 예시 동작:
# 내부 네트워크의 172.31.1.0에서 외부로 패킷을 전송하면, 패킷의 출발지 IP가 ens33의 IP(예: 192.168.34.10)로 변경됩니다.
# 반대로 응답 패킷은 NAT 테이블을 참조하여 내부 네트워크의 적절한 IP로 전달됩니다.

# iptables-persistent 패키지를 사용하여 영구 설정
# 방화벽 규칙 영구 저장
sudo apt-get update
sudo apt-get install iptables-persistent
sudo netfilter-persistent save            #이미 설정한 NAT 규칙 저장 명령어
sudo sh -c "iptables-save > /etc/iptables/rules.v4"  # NAT 규칙 수동으로 저장

# 호스트 네임 설정 
hostnamectl set-hostname sj-auth-bastion

telnet www.google.com 80이 Connected로 끝나고 ping 8.8.8.8을 실행한 것은, Bastion 자신이 ens33으로 외부에 나갈 수 있는지를 보는 확인이다.

같은 블록에서 ufw disable도 실행한다. 랩에서 SSH나 포워딩이 막히지 않게 끈 것이다.

사설망 노드가 외부로 나가려면 Bastion이 ens34에서 받은 패킷을 ens33으로 넘겨야 한다. 그래서 net.ipv4.ip_forward=1을 켜고 /etc/sysctl.conf에도 넣어 재부팅 뒤에도 유지한다.

이어서 iptables NAT 테이블에 -s 172.31.1.0/24 -o ens33 -j MASQUERADE를 넣는다. 사설망에서 나가는 패킷의 출발지 주소를 ens33의 192.168.34.226으로 바꿨다가, 응답은 NAT 테이블을 보고 원래 노드로 돌려준다. iptables -t nat -L --line-numbers에서 POSTROUTING 1번이 172.31.1.0/24 MASQUERADE이면, 방금 넣은 규칙은 들어간 것이다.

규칙을 재부팅 후에도 쓰려면 iptables-persistent로 저장한다. 호스트 이름은 sj-auth-bastion으로 맞춘다.

Master0103 번, worker0103에서 진행

마스터와 워커에는 사설망 ens34만 둔다. 아래 YAML의 172.31.1.2~4/24는 마스터 세 대를 한 번에 적은 표기다. 각 노드는 1편 표와 아래 /etc/hosts대로 자기 주소를 넣는다. 마스터는 172.31.1.2–172.31.1.4, 워커는 172.31.1.5–172.31.1.7이다. 기본 게이트웨이는 Bastion의 172.31.1.1이고, DNS는 8.8.8.8이다. 노드의 외부 통신은 이 게이트웨이를 거쳐 앞에서 넣은 NAT로 나간다.

root@k8s-hardway-master01~03:/etc/netplan# vi 00-installer-config.yaml
# This is the network config written by 'subiquity'
network:
  version: 2
  ethernets:
    ens34:
      addresses:
      - 172.31.1.2~4/24
      gateway4: 172.31.1.1
      nameservers: 
        addresses:
        - 8.8.8.8
        search: []
        
root@k8s-hardway-master01~03:/etc/netplan# sudo netplan apply 

# net-tools 설치 진행
root@k8s-hardway-master01~03:/etc/netplan# apt update -y

netplan apply 뒤에 올린 ifconfig에는 ens34가 172.31.1.4/24로 올라와 있다. 이어서 각 노드 호스트 이름을 k8s-hardway-master01–master03, k8s-hardway-worker01–worker03으로 맞춘다.

이 단계에서 노드에서 8.8.8.8로 ping하고, 노드 서로 간에도 ping해 통신이 되는지를 확인했다.

Bastion 서버에서 실행

Bastion의 /etc/hosts에 사설 IP와 호스트 이름을 넣어, 이후 편에서 이름만으로 노드에 접속할 수 있게 한다. 이 글에 나온 조회 결과는 Bastion의 파일이다.

root@sunjae-auth-bastion-192-168-34-226:~# cat << EOF >> /etc/hosts
127.0.0.1 localhost
172.31.1.2 k8s-hardway-master01
172.31.1.3 k8s-hardway-master02
172.31.1.4 k8s-hardway-master03
172.31.1.5 k8s-hardway-worker01
172.31.1.6 k8s-hardway-worker02
172.31.1.7 k8s-hardway-worker03

# 디렉토리 생성
root@sunjae-auth-bastion-192-168-34-226:~# mkdir hardway
root@sunjae-auth-bastion-192-168-34-226:~# cd hardway/
root@sunjae-auth-bastion-192-168-34-226:~/hardway# mkdir certs 
root@sunjae-auth-bastion-192-168-34-226:~/hardway# cd certs/

마지막으로 ~/hardway/certs를 만든다. 3편부터 인증서와 설정 파일을 이 디렉터리에서 다룬다.

이 단계에서 보면 되는 것은 다음과 같다.

  • Bastion ens33이 192.168.34.226, ens34가 172.31.1.1이고, Bastion에서 외부로 telnet·ping이 되는지
  • net.ipv4.ip_forward가 1이고, POSTROUTING에 172.31.1.0/24 MASQUERADE가 있는지
  • 각 노드 ens34 주소와 게이트웨이 172.31.1.1이 맞는지
  • Bastion /etc/hosts와 호스트 이름이 1편 표와 같은지

안 될 때 확인할 곳:

  • netplan apply 뒤에 SSH가 끊기면, ens33 주소·게이트웨이를 콘솔에서 다시 본다.
  • 노드는 나가는데 응답이 없으면 ip_forward와 MASQUERADE의 출발지 대역·-o ens33을 본다.
  • 노드 간 ping이 안 되면 같은 172.31.1.0/24에 올라왔는지, 호스트 방화벽을 본다.

여기까지 되면 사설망과 Bastion NAT가 준비된 것이다. 다음은 3편에서 CA와 클라이언트 인증서를 만든다.
