핵심 결론
CNPG는 PostgreSQL을 대체하지 않는다. AGE를 쓰려면 AGE가 들어 있는 이미지와 shared_preload_libraries·init SQL을 직접 넣어야 한다.

Kubernetes에서 PostgreSQL을 Operator로 운영할 때 CloudNativePG(CNPG) 를 쓰면 배포·복제·장애 복구·백업 같은 일을 차트와 CR로 묶을 수 있다. 여기에 Apache AGE 그래프 확장이 필요하면, Operator만 올린다고 AGE가 생기지는 않는다. AGE가 포함된 이미지와 init SQL을 cluster 차트 values에 넣는 PoC 구성을 정리한다.

글의 네임스페이스·시크릿·스토리지클래스·그래프 이름은 예시로 일반화했다. 비밀번호는 문서에 실값을 남기지 말고, 배포 전에 직접 넣는다.

1. CNPG란

CNPG(CloudNativePG)는 Kubernetes에서 PostgreSQL을 배포·운영·고가용성(HA) 관리하도록 돕는 오픈소스 Operator다. 설치, 복제, 장애 복구, 백업 같은 작업을 자동화하는 관리 계층이지, PostgreSQL 자체를 대체하는 데이터베이스는 아니다.

공식 사이트: cloudnative-pg.io

2. CNPG가 관리하는 기능

기능 설명
배포 및 설정 PostgreSQL 인스턴스와 설정 관리
고가용성(HA) Primary 장애 시 복제본 승격 및 복구
데이터 복제 PostgreSQL Streaming Replication 관리
백업 및 복구 백업 정책과 복구 절차 관리
스토리지 연동 PVC를 통한 영속 스토리지 사용
모니터링 PostgreSQL 상태 및 메트릭 수집 지원

자동으로 관리하더라도, 실제 장애 복구 성공 여부는 복제 상태·스토리지·네트워크·백업 구성에 영향을 받는다.

3. PostgreSQL과 CNPG의 차이

구분 PostgreSQL CNPG
종류 데이터베이스 Kubernetes Operator
역할 SQL 실행 및 데이터 저장 PostgreSQL 운영 자동화
실행 형태 서버 프로세스 Operator가 PostgreSQL Pod 등을 관리
고가용성 별도 구성 필요 복제·승격 등의 운영 자동화 지원
Kubernetes 의존성 없음 Kubernetes 환경에서 동작

4. Apache AGE를 붙일 때

관계 그래프를 PostgreSQL + Apache AGE에 두고, CNPG로 그 클러스터의 배포·복제·장애 복구를 맡기는 구성을 검토할 수 있다. 문서 검색·벡터 검색은 별도 저장소(예: OpenSearch)가 담당하는 식의 역할 분리가 자연스럽다.

다만 AGE를 쓰려면 다음을 직접 확인해야 한다.

  • CNPG가 관리하는 PostgreSQL 이미지에 AGE 확장이 포함되어 있는지
  • 그 이미지가 목표 PostgreSQL 버전과 호환되는지

CNPG를 도입한다고 AGE가 자동으로 설치되지는 않는다.

6. PostgreSQL Cluster (cluster chart) + AGE

Operator만 있는 상태이므로 cnpg/cluster 차트를 pull한 뒤 Secret → Helm install 순서다. AGE PoC라면 AGE 포함 이미지와 init SQL을 values에 넣는다.

kubectl create namespace age-demo

아래는 cluster chart values.yaml에서 바꾼 부분만 정리한 것이다. 나머지 chart 기본값은 그대로 둔다. storageClass는 환경에 맞게 바꾼다.

# --- 파일 맨 위 (추가) ---
# PoC: PostgreSQL + Apache AGE on CNPG cluster chart
# Install: helm upgrade --install age-pg ./cluster -n age-demo --wait
# Prerequisite: kubectl create secret ... (비밀번호를 고정할 때만)

# --- chart 기본 (변경 없음, 참고) ---
type: postgresql
mode: standalone
version:
  postgresql: "16"

# --- cluster: AGE PoC 수정 구간 ---
cluster:
  instances: 3
  imageName: ghcr.io/konnektr-io/age:16-1.6.0-standard-trixie
  storage:
    size: 20Gi
    storageClass: nfs-storage
  enablePDB: false
  postgresql:
    shared_preload_libraries:
      - age
  initdb:
    database: appdb
    owner: appuser
    # 비밀번호를 고정하려면 미리 Secret을 만들고 아래를 켠다.
    # secret:
    #   name: age-pg-app
    postInitApplicationSQL:
      - CREATE EXTENSION IF NOT EXISTS age;
      - LOAD 'age';
      - SET search_path = ag_catalog, "$user", public;
      - SELECT create_graph('infra_graph');

backups:
  enabled: false

원문 PoC에서는 인스턴스 수를 줄여 단일 인스턴스에 가깝게 쓰면서 enablePDB: false를 켠 흔적이 있다. HA를 보려면 인스턴스 수와 PDB 설정을 환경에 맞게 다시 잡는다.

helm install age-pg . -n age-demo --create-namespace --wait --timeout 15m

설치 후 Secret 확인

kubectl get secret -n age-demo
kubectl get secret -n age-demo -l cnpg.io/cluster=age-pg

Secret 이름은 Operator/차트 release명에 따라 {release}-app 형태일 수 있다. 비밀번호를 터미널에 그대로 찍지 말고, 필요하면 시크릿 매니저나 로컬에서만 확인한다.

7. 정리

단계 할 일
Operator cnpg/cloudnative-pg Helm 설치, CRD·Deployment Ready
Cluster cnpg/cluster values에 AGE 이미지·preload·init SQL
검증 Pod Running, Secret 존재, AGE extension·그래프 생성 SQL 적용

CNPG는 운영 자동화 계층이고, AGE는 이미지·preload·init SQL로 직접 심어야 한다. 이 두 층을 섞어 쓰지 않는 것이 이 PoC의 핵심이다.
