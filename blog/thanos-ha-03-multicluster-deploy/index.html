매니지먼트 클러스터에 MinIO·Thanos·Grafana를, 비즈니스 클러스터에 Sidecar가 붙은 Prometheus를 올리고 NodePort와 HAProxy로 gRPC·S3 경로를 잇는 values와 확인 방법, 시간 동기화 경고 해결까지 정리했다.

검증 조건

테스트 버전
  • Thanos v0.31.0
  • kube-prometheus-stack 66.4.0
  • MinIO chart 15.0.5
환경
Kubernetes 멀티 클러스터(매니지먼트 1 + 비즈니스 1), NodePort + HAProxy
핵심 결론
비즈니스 클러스터의 Sidecar는 NodePort로, 매니지먼트 클러스터의 MinIO는 NodePort 32000으로 열고, 클러스터 사이 gRPC는 HAProxy에서 반드시 TCP 모드로 넘긴다.

kind 시험으로 흐름을 확인한 뒤 실제 두 클러스터에 올린 절차다. 설계에서 정한 대로 매니지먼트 클러스터에는 MinIO, Thanos, Grafana를, 비즈니스 클러스터에는 Sidecar가 붙은 Prometheus를 둔다. 값에서 IP, 비밀번호, 호스트 이름은 모두 자리표시자로 바꿨다.

1. 매니지먼트 클러스터

1.1 MinIO Secret

Thanos가 MinIO에 붙는 설정이다. 같은 클러스터 안에서 접근하면 서비스 주소(minio.monitoring.svc.cluster.local:9000)를 쓰고, 비즈니스 클러스터처럼 밖에서 접근하면 노드 IP(또는 Bastion IP):NodePort를 쓴다.

# minio-key.yaml
type: s3
config:
  bucket: thanos
  endpoint: <NODE_IP>:32000
  access_key: <CHANGE_ME>
  secret_key: <CHANGE_ME>
  insecure: true
  signature_version2: true
kubectl create secret generic thanos-minio-secret -n monitoring --from-file=minio-key.yaml

1.2 MinIO 배포

MinIO를 NodePort로 열어 매니지먼트 클러스터 밖(비즈니스 클러스터)에서도 접근할 수 있게 한다.

# values-minio.yaml
mode: standalone
auth:
  rootUser: <CHANGE_ME>
  rootPassword: <CHANGE_ME>
defaultBuckets: thanos
replicaCount: 1
service:
  type: NodePort
  ports:
    api: 9000
    console: 9001
  nodePorts:
    api: "32000"
    console: "32001"
persistence:
  enabled: true
  storageClass: "nfs-client"
  mountPath: /bitnami/minio/data
  accessModes:
    - ReadWriteOnce
  size: 8Gi
helm install minio minio/minio --version 15.0.5 -f values-minio.yaml -n minio
kubectl get pods,svc -n minio

서비스는 9000:32000/TCP,9001:32001/TCP로 열린다.

1.3 HAProxy

클러스터 앞단에 둔 HAProxy가 노드들의 NodePort로 넘겨 준다. 두 클러스터 사이에서 MinIO API와 콘솔 포트를 열어 두는 설정이다. 백엔드는 노드 수만큼 server 줄을 반복한다.

listen minio-api
  bind *:32000
  mode tcp
  option tcplog
  server node-1 <NODE_IP>:32000 check inter 2000 rise 2 fall 5
  server node-2 <NODE_IP>:32000 check inter 2000 rise 2 fall 5

listen minio-console
  bind *:32001
  mode tcp
  option tcplog
  server node-1 <NODE_IP>:32001 check inter 2000 rise 2 fall 5
  server node-2 <NODE_IP>:32001 check inter 2000 rise 2 fall 5

1.4 Thanos 배포

매니지먼트 클러스터의 Query는 세 곳에서 데이터를 모은다. 비즈니스 클러스터의 Sidecar(NodePort), 매니지먼트 클러스터 안의 Store Gateway, 그리고 매니지먼트 클러스터 로컬 Prometheus의 Sidecar다. 그래서 query.stores에 세 주소를 모두 등록한다.

# values-thanos.yaml
objstoreConfig: |-
  type: s3
  config:
    bucket: thanos
    endpoint: <NODE_IP>:32000
    access_key: <CHANGE_ME>
    secret_key: <CHANGE_ME>
    insecure: true
    signature_version2: true
query:
  enabled: true
  dnsDiscovery:
    enabled: true
  stores:
    - <BASTION_IP>:10901                                      # 비즈니스 클러스터 Prometheus Sidecar (HAProxy 경유)
    - thanos-storegateway.monitoring.svc.cluster.local:10901  # 매니지먼트 클러스터 Store Gateway
    - prometheus-kube-prometheus-thanos-discovery:10901       # 매니지먼트 클러스터 로컬 Sidecar(실시간)
  extraArgs:
    - --query.replica-label=replica
    - --http-address=0.0.0.0:10902
    - --grpc-address=0.0.0.0:10901
  replicaCount: 3
  replicaLabel: prometheus_replica
bucketweb:
  enabled: true
compactor:
  enabled: true
  resourcesPreset: "none"
  persistence:
    enabled: false
storegateway:
  enabled: true
  persistence:
    enabled: false
  extraArgs:
    - --index-cache-size=500MB
    - --chunk-pool-size=2GB
ruler:
  enabled: true
  persistence:
    enabled: false
  alertmanagers:
    - http://prometheus-kube-prometheus-alertmanager.monitoring.svc.cluster.local:9093
  config: |-
    groups:
    - name: default
      rules: []

배포하면 thanos-query, thanos-query-frontend, thanos-storegateway, thanos-compactor, thanos-ruler, thanos-bucketweb Pod와 서비스가 올라온다. thanos-query-frontend는 NodePort로 열어 UI에 접근한다.

비즈니스 클러스터 Sidecar로 가는 경로에도 HAProxy를 둔다. gRPC라서 반드시 mode tcp로 해야 한다.

listen biz-thanos-discovery
  bind *:10901
  mode tcp
  server biz-node-1 <NODE_IP>:30901 check inter 2000 rise 2 fall 5
  server biz-node-2 <NODE_IP>:30901 check inter 2000 rise 2 fall 5

1.5 kube-prometheus-stack

매니지먼트 클러스터의 Grafana는 데이터 소스로 Thanos Query를 쓴다. 이중화한 Prometheus를 구분하는 라벨, 보존 기간, Sidecar 설정이 핵심이다.

# values-kube-prometheus-stack-mgmt.yaml
alertmanager:
  enabled: true
grafana:
  defaultDashboardsTimezone: Asia/Seoul
  adminPassword: <CHANGE_ME>
  additionalDataSources:
    - name: Thanos
      type: prometheus
      access: proxy
      url: http://thanos-query.monitoring.svc.cluster.local:9090
      isDefault: false
      editable: true
  persistence:
    enabled: true
    type: sts
    storageClassName: "nfs-client"
    accessModes:
      - ReadWriteOnce
    size: 20Gi
prometheus:
  thanosService:
    enabled: true
  prometheusSpec:
    replicas: 1
    retention: 5d
    retentionSize: "10GiB"
    scrapeInterval: "15s"
    externalLabels:
      cluster: management
    thanos:
      image: "quay.io/thanos/thanos:v0.31.0"
      objectStorageConfig:
        existingSecret:
          name: thanos-minio-secret
          key: minio-key.yaml
      version: v0.31.0
    additionalScrapeConfigs:
      - job_name: 'minio-metrics'
        metrics_path: /minio/v2/metrics/cluster
        static_configs:
          - targets: ['<MANAGEMENT-MINIO-IP>:32000']
helm install kube-prometheus-stack prometheus-community/kube-prometheus-stack \
  --version 66.4.0 -f values-kube-prometheus-stack-mgmt.yaml -n monitoring

Prometheus Pod 안의 데이터 디렉터리에는 2시간 단위 블록 디렉터리와 함께 thanos 디렉터리, thanos.shipper.json 파일이 생긴다. Sidecar가 블록을 올리고 있다는 흔적이다.

2. 비즈니스 클러스터

비즈니스 클러스터에는 kube-prometheus-stack만 올린다. Prometheus Pod에 Thanos Sidecar가 붙고, Grafana는 기본 Prometheus 데이터 소스만 쓴다. MinIO Secret은 매니지먼트 클러스터 쪽과 같은 형식이고 endpoint만 매니지먼트 클러스터 MinIO가 노출된 주소(<BASTION_IP>:32000)로 바꾼다.

# values-kube-prometheus-stack-biz.yaml
alertmanager:
  enabled: true
grafana:
  defaultDashboardsTimezone: Asia/Seoul
  adminPassword: <CHANGE_ME>
prometheus:
  thanosService:
    enabled: true
    type: NodePort
    clusterIP: ""
    nodePort: 30901   # NodePort는 30000-32767 범위만 가능
  prometheusSpec:
    replicas: 3
    retention: 5d
    retentionSize: "10GiB"
    scrapeInterval: "15s"
    externalLabels:
      cluster: business
    thanos:
      image: "quay.io/thanos/thanos:v0.31.0"
      objectStorageConfig:
        existingSecret:
          name: thanos-minio-secret
          key: minio-key.yaml
      version: v0.31.0
    additionalScrapeConfigs:
      - job_name: 'minio-metrics'
        metrics_path: /minio/v2/metrics/cluster
        static_configs:
          - targets: ['<MANAGEMENT-MINIO-IP>:32000']
kubeEtcd:
  enabled: true
  endpoints:
    - <NODE_IP>
    - <NODE_IP>
    - <NODE_IP>
  service:
    enabled: true
    port: 2381
    targetPort: 2381

kubeEtcd 블록은 etcd를 데몬으로 실행하는 클러스터에서 마스터 노드 IP를 직접 지정하는 경우다. 이 경우 TLS 설정은 비워 둘 수 있다.

helm install kube-prometheus-stack prometheus-community/kube-prometheus-stack \
  --version 66.4.0 -f values-kube-prometheus-stack-biz.yaml -n monitoring

3. 확인

매니지먼트 클러스터의 Thanos Query UI에서 확인한다.

  • /stores: 비즈니스 클러스터 Prometheus의 Sidecar와 매니지먼트 클러스터의 Store Gateway가 UP으로 등록되어 있어야 한다.
  • /targets: Prometheus 스크레이프 대상이 보인다.
  • MinIO 콘솔: thanos 버킷에 블록 디렉터리가 쌓인다.
  • Grafana: Thanos 데이터 소스를 쓰는 대시보드로 메트릭이 조회되는지 본다.

포트 포워딩이 안 될 때는 HAProxy에 Grafana와 MinIO 콘솔 포트를 하나씩 더 열어 접근했다.

4. 시간 동기화 경고

Query UI에 이런 경고가 떴다.

Warning: Error fetching server time: Detected 44.15 seconds time difference between your browser and the server. Thanos relies on accurate time and time drift...

경고 문구대로 Thanos는 정확한 시간에 의존한다. 서버 시간이 틀어져 있다는 뜻이라 chrony를 점검해서 맞췄다.

sudo vi /etc/chrony/chrony.conf

정상적인 공개 NTP 서버가 한두 개 이상 들어 있어야 한다. 국내 서버를 쓰면 이렇게 쓴다.

server time.bora.net iburst
server ntp1.kornet.net iburst

변경 후 재시작하고 수동으로 동기화한 뒤 상태를 본다.

sudo systemctl restart chronyd
sudo chronyc makestep
chronyc tracking
chronyc sources
timedatectl status

chronyc tracking에서 Leap status : Normal, timedatectl status에서 System clock synchronized: yes가 나오면 된다.

클러스터 배포 외부 노출
매니지먼트 클러스터 kube-prometheus-stack(Grafana → Thanos Query), Thanos, MinIO MinIO NodePort 32000(API)·32001(콘솔), Query Frontend NodePort
