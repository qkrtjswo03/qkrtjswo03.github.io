Bastion에서 worker01(172.31.1.5, k8s-hardway-worker01)의 kubelet 클라이언트 인증서와 kubeconfig를 수동으로 만든다.

Sections

  1. kubelet client 인증서 생성 (auth-bastion 에서 진행합니다. )
  2. kubelet kubeconfig 생성 (bastion 인스턴스에서 진행합니다. )
  3. docker 설치
  4. Binary 다운로드

잠긴 글입니다. 저장소 주인만 본문을 볼 수 있습니다.

8편에서 컨트롤 플레인을 올린 다음, 이 글에서는 워커01을 수동 인증서로 붙인다. 워커02·03의 부트스트랩 조인은 12편에서 다룬다.

kubelet client 인증서 생성 (auth-bastion 에서 진행합니다. )

  • IP.1 = 172.31.1.5
  • worker node 1의 ip 주소

구성 파일 SAN에는 워커01 주소 172.31.1.5와 이름 k8s-hardway-worker01이 들어 있다. 인증서 주체는 CN=system:node:k8s-hardway-worker01, 조직은 O=system:nodes다. CA는 3편에서 만든 ca.crt와 ca.key다.

openssl-k8s-hardway-worker01.cnf 인증서 생성 (워커01만 생성하면 됨) 
root@k8s-hardway-bastion:~/hardway/cert# cat > openssl-k8s-hardway-worker01.cnf <<EOF
[req]
req_extensions = v3_req
distinguished_name = req_distinguished_name

[req_distinguished_name]

[ v3_req ]
basicConstraints = CA:FALSE
keyUsage = nonRepudiation, digitalSignature, keyEncipherment
subjectAltName = @alt_names

[alt_names] 
IP.1 = 172.31.1.5  # worker01번 IP 
DNS.1 = k8s-hardway-worker01
EOF

root@sj-auth-bastion-192-168-34-226:~/hardway/certs# openssl genrsa -out k8s-hardway-worker01.key 2048
root@sj-auth-bastion-192-168-34-226:~/hardway/certs# openssl req -new -key k8s-hardway-worker01.key -subj "/CN=system:node:k8s-hardway-worker01/O=system:nodes" -out k8s-hardway-worker01.csr -config openssl-k8s-hardway-worker01.cnf
root@sj-auth-bastion-192-168-34-226:~/hardway/certs# openssl x509 -req -in k8s-hardway-worker01.csr -CA ca.crt -CAkey ca.key -CAcreateserial  -out k8s-hardway-worker01.crt -extensions v3_req -extfile openssl-k8s-hardway-worker01.cnf -days 365

  • master node 1의 ip 주소 ( or VIP : 172.31.1.8 )

호스트 이름과 같은 파일 이름의 인증서·키·kubeconfig와 ca.crt를 /etc/kubernetes 아래 경로로 복사한다.

  • kubelet-config.yaml ( worker01 )
root@k8s-hardway-worker01:/home/ubuntu/hardway/certs# cat << EOF | sudo tee /etc/kubernetes/kubelet-config.yaml
kind: KubeletConfiguration
apiVersion: kubelet.config.k8s.io/v1beta1
authentication:
  anonymous:
    enabled: false
  webhook:
    enabled: true
  x509:
    clientCAFile: "/etc/kubernetes/ssl/ca.crt"
authorization:
  mode: Webhook
clusterDomain: "cluster.local"
clusterDNS:
- 10.231.0.10
resolvConf: "/run/systemd/resolve/resolv.conf"
runtimeRequestTimeout: "15m"
EOF
세부 설명

  • anonymous: enabled: false → 익명 사용자의 Kubelet 접근을 비활성화합니다.

    → 인증되지 않은 접근을 차단하여 보안을 강화합니다.

  • webhook: enabled: true → Kubelet이 인증 요청을 Kubernetes API 서버의 Webhook으로 전달해 인증 절차를 처리합니다.

  • x509: clientCAFile: "/etc/kubernetes/ssl/ca.crt" → 클라이언트 인증서를 검증할 때 사용하는 CA 인증서 경로를 지정합니다.

    → "/etc/kubernetes/ssl/ca.crt" 파일은 Kubelet이 신뢰할 수 있는 인증서를 정의합니다.

  • clusterDomain: "cluster.local" → Kubernetes 클러스터의 기본 DNS 도메인 이름입니다.

    → 클러스터 내에서 서비스 이름을 DNS로 검색할 때 사용됩니다.

  • clusterDNS: - 10.231.0.10 → 클러스터 내의 Pod가 사용할 DNS 서버의 IP 주소를 지정합니다.

    → 일반적으로 CoreDNS 또는 kube-dns가 제공하는 DNS 서비스의 IP입니다.

  • resolvConf: "/run/systemd/resolve/resolv.conf" → Kubelet이 사용하는 DNS 설정 파일의 경로입니다.
