GPU 노드에 NVIDIA 드라이버를 패키지로 직접 설치하고, GPU Operator v24.9.2를 driver 비활성화 옵션으로 배포했다. 드라이버를 DaemonSet으로 두지 않은 이유와 mig-manager 추가 설정, 노드 라벨 읽는 법까지 정리했다.

검증 조건

테스트 버전
  • GPU Operator v24.9.2
  • nvidia-driver-550
  • Ubuntu 22.04
  • containerd
환경
OpenStack VM 위 Kubernetes, NVIDIA A100 PCIe 40GB
검증 시점
2025-03
핵심 결론
드라이버는 호스트에 패키지로 깔고 GPU Operator는 driver.enabled=false로 올린다. 사전 설치 드라이버를 쓰면 mig-manager가 재시작할 서비스 목록을 따로 알려줘야 한다.

개요에서 정리한 시험을 하려면 먼저 GPU 노드가 Kubernetes 리소스로 보여야 한다. 이 글은 A100 노드에 드라이버를 올리고 GPU Operator를 배포해 nvidia.com/gpu가 노드에 등록되기까지의 과정이다.

드라이버를 DaemonSet으로 두지 않은 이유

GPU Operator는 드라이버도 Pod(DaemonSet)로 설치할 수 있다. 하지만 이번에는 호스트에 직접 설치하는 쪽을 택했다. 이유는 두 가지다.

  • 노드에서 nvidia-smi를 바로 쓸 수 없다. 드라이버가 Pod 안에 있으면 GPU에 접근할 수 있는 Pod에 들어가야 nvidia-smi를 실행할 수 있다. 호스트에 설치하면 노드에서 바로 확인한다.
  • 드라이버 Pod와 노드에 OOM이 반복됐다. 이 구성으로 바꾸기 전에 드라이버를 DaemonSet으로 배포했을 때 Pod와 노드 모두 OOM이 되풀이됐다. 당시 GPU 노드의 유휴 메모리는 8Gi였다.

폐쇄망을 고려한 바이너리 설치 방법은 아직 정리하지 못했고, 지금은 패키지 설치만 다룬다.

NVIDIA 드라이버 설치(Ubuntu)

ubuntu-drivers로 권장 버전을 확인한다. 결과에서 recommended가 붙은 항목이 권장 버전이다.

ubuntu-drivers devices
== /sys/devices/pci0000:00/0000:00:05.0 ==
model    : GA100 [A100 PCIe 40GB]
driver   : nvidia-driver-535 - distro non-free
driver   : nvidia-driver-550 - distro non-free recommended
driver   : nvidia-driver-570-server - distro non-free
...

권장 버전을 자동 설치한다. 이번에는 nvidia-driver-550이 깔렸다.

ubuntu-drivers autoinstall

설치가 끝나면 해당 노드에서 nvidia-smi가 동작한다.

NVIDIA-SMI 550.120    Driver Version: 550.120    CUDA Version: 12.4
GPU 0  NVIDIA A100-PCIE-40GB    MIG M.: Disabled

권장 버전은 계속 바뀌므로 설치 전에 NVIDIA 공식 드라이버 페이지에서 GPU 모델과 OS에 맞는 Data Center Driver를 확인하는 편이 낫다. 시험 시점에 Ubuntu 22.04와 RHEL 9용으로 올라와 있던 최신 버전은 580.65.06(CUDA 13.0)이었다. 드라이버를 다른 쪽에서 설치해 준다면 nvidia-smi가 실행되는지만 확인하고 다음 단계로 넘어가면 된다.

GPU Operator 배포

Helm 저장소를 추가한다.

helm repo add nvidia https://helm.ngc.nvidia.com/nvidia && helm repo update

차트는 v24.9.2를 썼다. 드라이버는 이미 호스트에 있으니 driver.enabled=false로 끄고, containerd 설정을 Operator에 알려 준다.

helm upgrade --install --wait gpu-operator \
  -n gpu-operator \
  nvidia/gpu-operator \
  --version=v24.9.2 \
  --set toolkit.env[0].name=CONTAINERD_CONFIG \
  --set toolkit.env[0].value=/etc/containerd/config.toml \
  --set toolkit.env[1].name=CONTAINERD_SOCKET \
  --set toolkit.env[1].value=/run/containerd/containerd.sock \
  --set toolkit.env[2].name=CONTAINERD_RUNTIME_CLASS \
  --set toolkit.env[2].value=nvidia \
  --set toolkit.env[3].name=CONTAINERD_SET_AS_DEFAULT \
  --set driver.enabled=false \
  --set-string toolkit.env[3].value=true \
  --set dcgmExporter.serviceMonitor.honorLabels=true

각 옵션의 뜻은 이렇다.

옵션 역할
CONTAINERD_CONFIG 사용 중인 containerd 설정 파일 경로
CONTAINERD_SOCKET containerd 소켓 경로
CONTAINERD_RUNTIME_CLASS GPU 컨테이너용 RuntimeClass 이름(nvidia)
CONTAINERD_SET_AS_DEFAULT 모든 컨테이너의 기본 런타임을 nvidia로 지정
driver.enabled Operator가 드라이버를 배포할지 여부
dcgmExporter.serviceMonitor.honorLabels namespace 라벨이 겹치는 문제 때문에 false에서 true로 바꿨다

honorLabels가 적용되지 않았다면 차트 values.yaml의 dcgmExporter.serviceMonitor에 honorLabels: true를 직접 넣는다.

사전 설치 드라이버를 위한 mig-manager 설정

mig-manager는 MIG 구성을 바꿀 때 GPU에 접근하는 Operator 관리 Pod를 모두 재시작한다. 드라이버를 호스트에 먼저 깔았다면, 같은 목적으로 재시작해야 할 호스트 서비스도 알려 주어야 한다. 서비스 목록 파일을 만들고 ConfigMap으로 올린 뒤 ClusterPolicy에 연결한다.

# clients.yaml
version: v1
systemd-services:
  - nvsm.service
  - nvsm-mqtt.service
  - nvsm-core.service
  - nvsm-api-gateway.service
  - nvsm-notifier.service
  - nv_peer_mem.service
  - nvidia-dcgm.service
  - dcgm.service
  - dcgm-exporter.service
kubectl create configmap -n gpu-operator gpu-clients --from-file=clients.yaml
kubectl edit clusterpolicy -n gpu-operator cluster-policy
spec:
  migManager:
    gpuClientsConfig:
      name: gpu-clients

노드 라벨 읽기

Operator가 올라가면 NFD와 GFD가 GPU 노드에 라벨을 붙인다. 이후 글에서 계속 쓰게 될 항목은 다음과 같다.

nvidia.com/gpu.count=1
nvidia.com/gpu.product=NVIDIA-A100-PCIE-40GB
nvidia.com/gpu.family=ampere
nvidia.com/gpu.memory=40960
nvidia.com/gpu.replicas=1
nvidia.com/gpu.sharing-strategy=none
라벨 뜻
gpu.count 사용할 수 있는 GPU 개수
gpu.product 제품명. Time-Slicing이 적용되면 뒤에 SHARED가 붙는다
gpu.replicas GPU 리소스의 복제 수. Time-Slicing으로 늘릴 수 있다
gpu.sharing-strategy none이면 공유하지 않고, time-slicing이면 공유한다

이 라벨들이 Time-Slicing이나 MIG를 켰을 때 어떻게 바뀌는지가 각 방식을 확인하는 가장 빠른 방법이었다.
