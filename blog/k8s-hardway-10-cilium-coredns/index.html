Bastion에서 Helm으로 Cilium 1.15.4를 kube-system에 설치하고, RBAC와 CoreDNS를 구성한다.

Sections

  1. auth-bastion 에서 Helm Chart를 활용한 CNI Plugin 설치
  2. 로그 권한을 위한 Clusterrole, Clusterrolebinding
  3. CoreDNS

잠긴 글입니다. 저장소 주인만 본문을 볼 수 있습니다.

9편에서 worker01을 조인했지만, 오버레이 네트워크가 없어 노드는 NotReady였다. 이 편에서는 Bastion에서 CNI로 Cilium을 설치하고, API 서버가 kubelet 로그를 볼 수 있게 RBAC를 만든 다음, CoreDNS를 구성한다. 노드가 Ready로 바뀌는지는 여기서 확인하고, DNS·Service 통신은 11편에서 본다.

쿠버네티스에서 Pod가 IP를 받고 노드 사이에 통신하려면 CNI 플러그인이 필요하다. CNI가 없으면 kubelet은 노드를 Ready로 올리지 않는다. 9편 끝의 NotReady가 이 상태다.

이 랩의 CNI는 1편에서 정한 Cilium v1.15.4다. Cilium은 eBPF 기반 CNI이고, Helm 차트로 kube-system에 설치한다.

auth-bastion 에서 Helm Chart를 활용한 CNI Plugin 설치

로그 권한을 위한 Clusterrole, Clusterrolebinding

이 RBAC는 kube-apiserver가 kubelet의 nodes/log, nodes/proxy, nodes/stats, nodes/spec, nodes/metrics API를 호출하기 위한 것이다. 1편에서 말한 pod log, pod exec가 이 권한에 해당한다. ClusterRole system:kube-apiserver-to-kubelet에 동사를 넣고, ClusterRoleBinding system:kube-apiserver로 User kube-apiserver에 연결한다.

  • clusterrolebinding.yaml

root@sj-auth-bastion-192-168-34-226:~/hardway/certs# cat << EOF > kubelet-clusterrolebinding.yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: system:kube-apiserver
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: system:kube-apiserver-to-kubelet
subjects:
  - kind: User
    name: kube-apiserver
    apiGroup: rbac.authorization.k8s.io
EOF

CoreDNS

CoreDNS는 클러스터 내부 DNS다. kubernetes.default.svc.cluster.local 같은 서비스 이름을 ClusterIP로 풀어 주고, 외부 이름은 Corefile의 forward . /etc/resolv.conf로 넘긴다.

Service clusterIP는 10.231.0.10이다. 이 값은 9편 kubelet 설정의 clusterDNS와 같고, 8편에서 넣은 서비스 CIDR 10.231.0.0/18 안에 있다. 이미지 태그는 coredns/coredns:1.6.5다.


---
root@sj-auth-bastion-192-168-34-226:~/hardway/certs# vi coredns.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: coredns
  namespace: kube-system
  labels:
      addonmanager.kubernetes.io/mode: EnsureExists
data:
  Corefile: |
    .:53 {
        errors
        health {
            lameduck 5s
        }
        ready
        kubernetes cluster.local in-addr.arpa ip6.arpa {
          pods insecure
          fallthrough in-addr.arpa ip6.arpa
        }
        prometheus :9153
        forward . /etc/resolv.conf {
          prefer_udp
        }
        cache 30
        loop
        reload
        loadbalance
    }
---
