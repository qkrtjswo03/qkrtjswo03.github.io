핵심 결론
Promtail dependency를 주석 처리하고 Alloy DaemonSet + river 설정으로 /var/log/pods 로그를 Loki push API에 보내면 된다.

로그 수집기를 Promtail 에서 Grafana Alloy 로 바꿀 때, Helm 패키지 안에서 dependency·values·ConfigMap 기본 설정을 같이 손봐야 한다. Alloy chart를 받아 넣고, DaemonSet으로 Pod 로그를 모아 Loki gateway로 보내는 구성을 정리한다.

기존 Promtail 의존성을 끄고 Alloy chart로 같은 Loki 게이트웨이에 로그를 보내는 과정이다.

이미지 레지스트리 호스트·패키지 경로는 예시로 일반화했다. registry.example.internal:50000 자리와 release/차트 경로는 환경에 맞게 바꾼다.

1. Alloy Helm chart 받기

작업 위치는 모니터링 패키지 루트(예: monitoring-pack/)를 기준으로 한다.

helm repo add grafana https://grafana.github.io/helm-charts
helm repo update
helm pull grafana/alloy --version 1.2.1 --untar -d charts/
  • Grafana Helm 저장소 추가
  • Alloy chart v1.2.1 다운로드
  • charts/alloy 경로에 압축 해제

Grafana Helm 저장소에서 Alloy chart 1.2.1을 받아 charts/ 아래에 푼다.

2. 루트 values에서 Promtail 끄고 Alloy 켜기

경로 예: monitoring-pack/values.yaml

기존 Promtail 블록은 주석으로 남기고, Alloy를 켠다.

Promtail 설정은 주석으로 남기고 Alloy를 켠다. 이미지는 v1.10.1이고, /var/log 마운트를 켠다. 컨트롤 플레인·마스터 톨러레이션으로 해당 노드에도 스케줄할 수 있게 한다.

# promtail:
#   image:
#     registry: registry.example.internal:50000
#     repository: prometheus-stack/grafana/promtail
#     tag: "3.0.0"
#   config:
#     clients:
#     - url: http://prometheus-stack-loki-distributed-gateway.monitoring.svc.cluster.local/loki/api/v1/push

alloy:
  enabled: true
  image:
    registry: registry.example.internal:50000
    repository: prometheus-stack/grafana/alloy
    tag: "v1.10.1"
  configReloader:
    enabled: false
  rbac:
    create: true
  serviceAccount:
    create: true
  mounts:
    varlog: true
    dockercontainers: false
  controller:
    daemonset:
      tolerations:
        - key: node-role.kubernetes.io/control-plane
          operator: Exists
          effect: NoSchedule
        - key: node-role.kubernetes.io/master
          operator: Exists
          effect: NoSchedule
  • DaemonSet으로 노드마다 로그 수집
  • control-plane 노드에도 스케줄 허용
  • /var/log 마운트 활성화

Chart.lock에는 Alloy 1.2.1과 loki-distributed 0.80.2 등이 잡힌다. Promtail dependency는 제거(또는 주석)한다.

Chart.yaml에서는 Promtail 의존성을 주석 처리하고, Alloy 1.2.1과 기존 loki-distributed 0.80.2를 함께 둔다.

4. Alloy river 설정

경로 예: monitoring-pack/charts/alloy/config/river.alloy (신규)

loki.write "loki" {
  endpoint {
    url         = "http://prometheus-stack-loki-distributed-gateway.monitoring.svc.cluster.local/loki/api/v1/push"
    batch_wait  = "1s"
    batch_size  = "1MiB"
  }
}

discovery.kubernetes "pods" {
  role = "pod"
}

discovery.relabel "pod_logs" {
  targets = discovery.kubernetes.pods.targets

  rule {
    source_labels = ["__meta_kubernetes_namespace"]
    action        = "replace"
    target_label  = "namespace"
  }

  rule {
    source_labels = ["__meta_kubernetes_pod_name"]
    action        = "replace"
    target_label  = "pod"
  }

  rule {
    source_labels = ["__meta_kubernetes_pod_container_name"]
    action        = "replace"
    target_label  = "container"
  }

  rule {
    source_labels = ["__meta_kubernetes_pod_label_app_kubernetes_io_name"]
    action        = "replace"
    target_label  = "app"
  }

  rule {
    source_labels = ["__meta_kubernetes_namespace", "__meta_kubernetes_pod_container_name"]
    action        = "replace"
    target_label  = "job"
    separator     = "/"
    replacement   = "$1"
  }

  rule {
    source_labels = ["__meta_kubernetes_pod_uid", "__meta_kubernetes_pod_container_name"]
    action        = "replace"
    target_label  = "__path__"
    separator     = "/"
    replacement   = "/var/log/pods/*$1/*.log"
  }
}

loki.source.kubernetes "pod_logs" {
  targets    = discovery.relabel.pod_logs.output
  forward_to = [loki.process.pod_logs.receiver]
}

loki.process "pod_logs" {
  stage.json {
    expressions = { level = "level" }
  }
  stage.regex {
    expression = "(?i)(?P<level>error|warn|warning|info|debug|trace)"
  }
  stage.labels {
    values = { level = "level" }
  }
  stage.static_labels {
    values = {
      job    = "kubernetes",
      stream = "stdout",
    }
  }
  forward_to = [loki.write.loki.receiver]
}
  • Kubernetes Pod 자동 탐색
  • /var/log/pods 경로 기반 수집
  • level 라벨 추출
  • Loki gateway로 push

파드를 자동으로 찾고, /var/log/pods 경로의 로그를 모아 레벨 라벨을 붙인 뒤 Loki 게이트웨이의 push API로 보낸다.

5. ConfigMap 템플릿·서브차트 values

경로 예: monitoring-pack/charts/alloy/templates/configmap.yaml

data:
  {{- if $values.configMap.content }}
  config.alloy: |- {{- (tpl  $values.configMap.content .) | nindent 4 }}
  {{- else }}
  config.alloy: |- {{- .Files.Get "config/river.alloy" | trim | nindent 4 }}
  {{- end }}

values에 별도 configMap.content가 없으면 config/river.alloy를 기본으로 쓴다.

값에 별도 내용이 없으면 이 river 파일을 ConfigMap에 넣는다.

경로 예: monitoring-pack/charts/alloy/values.yaml

mounts:
  # Mount /var/log from the host into the container for log collection.
  varlog: true

7. 적용

영향 범위

모니터링 release가 업그레이드되며 Alloy DaemonSet이 배포·재시작되고, Promtail을 제거했다면 기존 Promtail Pod는 내려간다. 전환 순간 로그 수집이 잠시 비거나 중복될 수 있다.

의존성을 갱신한 뒤 같은 모니터링 패키지를 업그레이드한다.

helm dependency update
helm upgrade --install prometheus-stack .
