10편에서 Cilium과 CoreDNS를 설치했다. 이 편에서는 netshoot으로 클러스터 DNS와 Pod·Service 통신이 되는지를 확인한다. 확인이 끝나면 12편에서 worker02·03을 TLS Bootstrap으로 조인한다.

netshoot 디버깅 컨테이너 생성 (통신테스트)

통신을 확인하려고 netshoot을 DaemonSet으로 띄운다. tolerations가 Exists라서 스케줄 가능한 노드마다 한 개씩 올라간다. 지금은 worker01만 있으니 Pod도 하나다.

root@sj-auth-bastion-192-168-34-226:~/hardway/certs# vi netshoot.yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: netshoot-cluster
  labels:
    app: netshoot-cluster
spec:
  selector:
    matchLabels:
      name: netshoot-cluster
  template:
    metadata:
      labels:
        name: netshoot-cluster
    spec:
      tolerations:
      - operator: Exists
      containers:
      - name: netshoot-cluster
        tty: true
        stdin: true
        args:
        - bash
        image: nicolaka/netshoot
root@sj-auth-bastion-192-168-34-226:~/hardway/certs# kubectl apply -f  netshoot.yaml

  • echo-server

Service 경로를 보려고 echo 서버를 레플리카 2개로 띄운다. 각 Pod는 자기 hostname을 담은 HTML을 8080 포트로 응답한다. 이어서 ClusterIP 서비스 echo를 만들어 두 Pod로 보낸다.

root@sj-auth-bastion-192-168-34-226:~/hardway/certs# vi echo-server.yaml

apiVersion: apps/v1
metadata:
  name: service-test
spec:
  replicas: 2
  selector:
    matchLabels:
      app: service_test_pod
  template:
    metadata:
      labels:
        app: service_test_pod
    spec:
      containers:

        image: python:2.7
        imagePullPolicy: IfNotPresent
        command: ["/bin/bash"]
        args: ["-c", "echo \"<p>Hello from $(hostname)</p>\" > index.html; python -m SimpleHTTPServer 8080"]

        - name: http
          containerPort: 8080

worker01에서 Cilium 에이전트, CoreDNS, netshoot, echo Pod 두 개가 모두 1/1 Running이다. echo Pod IP는 10.0.0.70, 10.0.0.106이고, CoreDNS는 10.0.0.176이다.

같은 목록에서 cilium-operator 하나는 Running이고, 다른 하나는 Pending이다. cilium-operator는 기본 2개를 서로 다른 노드에 띄운다. 이 시점에는 worker01만 있어서 한쪽이 Pending으로 남았다. 12편에서 worker02·03을 붙인 뒤에는 둘 다 Running이다.

kubectl get svc에서 coredns는 10.231.0.10, echo는 10.231.58.2이다. hubble-peer도 목록에 있는데, 10편 Helm 안내에 Hubble이 포함됐다고 나온 것과 맞다. echo에 ClusterIP가 할당되면 서비스 생성은 된 것이다.

## 쿠버네티스 클러스터 내부에서 
netshoot-cluster-zk7pt:~# nslookup echo
Server:		10.231.0.10

## echo 는 로드밸런서 역할을 하여 라운드 로빈으로 접속
netshoot-cluster-zk7pt:~# curl echo:8080
<p>Hello from service-test-6b8c8fdb64-k6x4f</p>

netshoot-cluster-zk7pt:~# curl echo:8080
<p>Hello from service-test-6b8c8fdb64-7cdws</p>

10.0.0.106:8080으로 직접 접속해 Hello from service-test-6b8c8fdb64-k6x4f가 오면, CNI가 할당한 Pod IP로 HTTP 통신이 되는 것이다.

nslookup echo의 답이 echo.kube-system.svc.cluster.local의 10.231.58.2다. CoreDNS가 서비스 이름을 ClusterIP로 풀어 준 것이고, 주소는 위에서 본 echo 서비스와 같다. netshoot과 echo를 kube-system 네임스페이스에 띄워서, 짧은 이름 echo가 Pod의 DNS 검색 도메인을 따라 echo.kube-system.svc.cluster.local로 풀린 것이다.

같은 curl echo:8080을 두 번 실행하면 응답 hostname이 k6x4f와 7cdws로 갈린다. 서비스가 두 백엔드로 번갈아 보낸 것이다. 두 Pod hostname이 번갈아 나오면 이 단계는 성공이다.

안 될 때 확인할 곳

  • CoreDNS Pod가 kube-system에서 Running인지 본다.
  • Service selector와 endpoints가 대상 Pod 라벨·IP와 맞는지 본다.
  • Cilium 에이전트가 해당 노드에서 Running인지, 노드가 Ready인지 본다.

여기까지 되면 10편에서 설치한 CNI와 DNS가 동작하는 것이다. 다음 12편에서 worker02·03을 TLS Bootstrap으로 조인한다. Cilium에서 네트워크 정책을 L3·L4·L7로 나눠 확인한 내용은 Cilium Network Policy 글에 있다.
