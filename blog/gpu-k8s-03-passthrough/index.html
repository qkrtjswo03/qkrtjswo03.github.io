검증 조건

환경
OpenStack VM 위 Kubernetes, NVIDIA A100 PCIe 40GB, GPU Operator
검증 시점
2025-03
핵심 결론
Passthrough는 resources에 nvidia.com/gpu만 적으면 된다. 노드를 재기동하면 기존 Pod는 UnexpectedAdmissionError로 남으니 직접 지워야 한다.

가장 단순한 방식부터 확인했다. GPU Operator는 따로 설정하지 않으면 GPU를 Passthrough 방식으로 쓴다. Pod가 nvidia.com/gpu를 요청하면 GPU 한 장이 그 Pod에 독점으로 할당된다.

1. Pod에 GPU 할당

nvidia-device-plugin이 GPU를 확장 리소스로 등록하면 resources.limits에 그 이름을 적어 요청할 수 있다. 정리하면 Pod 스펙에서 손댈 곳은 두 군데다.

  • resources.limits의 nvidia.com/gpu: 필요한 GPU 수. 노드 라벨 nvidia.com/gpu.count만큼까지 쓸 수 있다.
  • runtimeClassName: nvidia: 컨테이너가 GPU에 접근할 수 있게 nvidia-container-runtime을 지정한다.
apiVersion: apps/v1
kind: Deployment
metadata:
  name: tensorflow-jupyterlab
  labels:
    app: tensorflow-jupyter
spec:
  replicas: 1
  selector:
    matchLabels:
      app: tensorflow-jupyter
  template:
    metadata:
      labels:
        app: tensorflow-jupyter
    spec:
      runtimeClassName: nvidia
      nodeSelector:
        kubernetes.io/hostname: gpu-node-1
      containers:
      - name: jupyter
        image: tensorflow/tensorflow:2.15.0-gpu-jupyter
        ports:
        - containerPort: 8888
        command: ["jupyter", "lab", "--ip=0.0.0.0", "--allow-root", "--no-browser"]
        resources:
          limits:
            nvidia.com/gpu: 1
        securityContext:
          privileged: true
      tolerations:
      - effect: NoSchedule
        key: nvidia.com/gpu

배포하고 Pod가 Running이 되면 안에 들어가 nvidia-smi로 GPU가 보이는지 확인한다.

kubectl apply -f tensorflow.yaml
kubectl get pods
kubectl exec -it <pod-name> -- nvidia-smi

실제로 쓰는지 확인

보이는 것과 쓰는 것은 다르다. Pod 안에서 TensorFlow로 행렬 곱을 반복하는 스크립트를 돌려, 실행 중에 nvidia-smi의 GPU 메모리 사용량이 늘어나는지 봤다.

import tensorflow as tf
import time

gpus = tf.config.list_physical_devices('GPU')
if not gpus:
    print("GPU가 인식되지 않았습니다.")
    exit()
print(f"사용 가능한 GPU 장치: {gpus}")

for gpu in gpus:
    tf.config.experimental.set_memory_growth(gpu, True)

start_time = time.time()
matrix_size = 5000
iterations = 100
a = tf.random.uniform((matrix_size, matrix_size), minval=0, maxval=1)
b = tf.random.uniform((matrix_size, matrix_size), minval=0, maxval=1)
for i in range(iterations):
    result = tf.matmul(a, b)
    if i % 10 == 0:
        print(f"{i}번째 연산 완료")
print(f"테스트 완료! 총 소요 시간: {time.time() - start_time:.2f}초")

2. 노드 재기동 뒤에도 자원이 유지되나

GPU가 할당된 Pod가 있는 상태에서 노드를 재기동했다. 기존 Pod는 UnexpectedAdmissionError 상태로 남고, Deployment가 새 Pod를 만들어 GPU를 다시 받았다. 새 Pod 안의 nvidia-smi에서 같은 A100 PCIe 40GB가 보였다. 남은 에러 Pod는 자동으로 사라지지 않아서 직접 삭제해야 한다.

NAME                                     READY   STATUS                      RESTARTS   AGE
tensorflow-jupyterlab-74bf7d9bd5-7mbfn   0/1     UnexpectedAdmissionError    0          15m
tensorflow-jupyterlab-74bf7d9bd5-vglbb   1/1     Running                     0          3m23s

3. 수정: GPU Pod와 일반 Pod 사이 오가기

이미 만든 Deployment에서 GPU 설정만 넣고 빼도 되는지 확인했다. 여기서 일반 Pod는 GPU를 받지 않는 Pod다.

  • GPU → 일반: 매니페스트에서 runtimeClassName: nvidia와 nvidia.com/gpu 리소스를 지우고 kubectl apply. 새 Pod에서는 nvidia-smi: command not found가 나온다.
  • 일반 → GPU: 두 항목을 다시 넣고 kubectl apply. 새 Pod에서 nvidia-smi가 GPU를 보여 준다.

둘 다 Pod를 새로 만들어 반영되므로 별도 작업은 필요 없었다.

4. 회수: Pod를 지우면 GPU가 돌아오나

GPU를 쓰는 Pod를 삭제하면 점유하던 GPU가 반환된다. 같은 매니페스트로 다시 배포하면 새 Pod가 GPU를 정상적으로 받아 nvidia-smi에 보였다.

정리

항목 결과
GPU 할당 nvidia.com/gpu: 1과 runtimeClassName: nvidia로 가능
노드 재기동 새 Pod가 GPU를 다시 받음. 기존 UnexpectedAdmissionError Pod는 수동 삭제
수정 매니페스트에서 GPU 항목을 넣고 빼는 것으로 전환 가능
회수 Pod 삭제 시 반환, 재배포 시 재할당
메트릭 Pod별 GPU 사용량 확인 가능
