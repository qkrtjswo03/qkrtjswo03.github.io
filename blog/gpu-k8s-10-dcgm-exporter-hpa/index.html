DCGM Exporter 메트릭을 Prometheus로 모으고 GPU 메모리로 HPA 걸기

SSunJae작성 2026.11.1210분 읽기조회 —공개

검증 조건

테스트 버전
  • kube-prometheus-stack 66.2.1
  • GPU Operator v24.9.2
환경
OpenStack VM 위 Kubernetes, NVIDIA A100 PCIe 40GB, MIG 1g.5gb
검증 시점
2025-03
핵심 결론
DCGM Exporter 메트릭을 PrometheusRule과 Prometheus Adapter로 Custom Metric에 올리면 GPU 메모리 사용량으로 HPA를 걸 수 있다. 메트릭을 못 얻는 Time-Slicing에서도 같은 방법으로 시험했다.

GPU Operator를 올리면 nvidia-dcgm-exporter가 GPU 상태를 Prometheus 형식으로 내보낸다. 이 글은 그 메트릭을 Prometheus로 수집하는 설정과, 수집한 값으로 HPA를 구성한 과정이다. 시리즈 앞부분의 시험에서 쓴 방법을 한곳에 모았다.

1. 수집 설정: additionalScrapeConfigs

kube-prometheus-stack을 배포할 때 additionalScrapeConfigs에 DCGM Exporter가 떠 있는 네임스페이스를 대상으로 하는 job을 추가한다. relabel_configs로 Pod가 떠 있는 노드 이름을 node 라벨로 붙인다.

# gpu-kube-prometheus-stack-values.yaml 예시
prometheus:
  prometheusSpec:
    additionalScrapeConfigs:
    - job_name: gpu-metrics
      scrape_interval: 1s
      metrics_path: /metrics
      scheme: http
      kubernetes_sd_configs:
      - role: endpoints
        namespaces:
          names:
          - gpu-operator  # dcgm-exporter가 배포된 네임스페이스
      relabel_configs:
      - source_labels: [__meta_kubernetes_pod_node_name]
        action: replace
        target_label: node

scrape_interval은 시험 중 변화를 바로 보려고 1초로 줬다. 운영에서는 값을 따로 정하는 편이 맞다.

helm install kube-prometheus-stack -n monitoring --create-namespace \
  ./kube-prometheus-stack-66.2.1.tgz -f gpu-kube-prometheus-stack-values.yaml

2. Pod별 사용량이 보이는 방식, 안 보이는 방식

수집 설정은 같아도 GPU를 어떻게 나눴느냐에 따라 Pod별 사용량이 보이는지가 갈린다.

방식 Pod별 GPU 사용량
Passthrough 보임
MIG 보임
Time-Slicing 보이지 않음
MIG + Time-Slicing 보이지 않음

Time-Slicing은 메트릭 추적을 지원하지 않는다. GPU 메모리를 프로세스별로 격리하지 않고 공유하기 때문에 nvidia-smi나 DCGM에서도 전체 사용량만 나온다. Pod 단위 모니터링이 필요한 구성이면 이 점부터 확인해야 한다. 아래 HPA는 GPU 메모리 사용량 평균을 기준으로 하기 때문에 Time-Slicing에서도 시험할 수 있었다. 또 GPU Operator를 설치할 때 dcgmExporter.serviceMonitor.honorLabels=true를 준 것은 namespace 라벨이 겹치는 문제 때문이었다.

3. GPU 메모리로 HPA 걸기

Kubernetes HPA는 보통 metrics-server의 CPU·메모리를 본다. GPU 사용량으로 스케일하려면 Custom Metrics API로 값을 노출해야 하고, 구성 요소는 세 가지다.

  • PrometheusRule: DCGM 메트릭을 Custom Metric으로 변환
  • Prometheus Adapter: 변환된 메트릭을 Custom Metrics API로 노출
  • HPA: Custom Metric 기준으로 스케일링

PrometheusRule

DCGM_FI_DEV_FB_USED(GPU 프레임버퍼 사용량)를 기준으로 삼았다. namespace와 app 단위로 평균을 낸 뒤 정수로 내림해 cuda_test_gpu_avg라는 이름의 레코딩 룰로 저장한다.

apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: cuda-test
  namespace: monitoring
  labels:
    app: kube-prometheus-stack
    release: kube-prometheus-stack
spec:
  groups:
  - name: gpu-rule-group
    rules:
    - record: cuda_test_gpu_avg
      expr: floor(avg by(namespace, app)(DCGM_FI_DEV_FB_USED))
      labels:
        namespace: default
        deployment: cuda-test

Prometheus Adapter

helm upgrade --install prometheus-adapter prometheus-community/prometheus-adapter \
  -n monitoring \
  --set prometheus.url="http://kube-prometheus-stack-prometheus.monitoring.svc.cluster.local"

Adapter가 메트릭을 제대로 노출하는지는 API를 직접 조회해서 확인한다.

kubectl get --raw /apis/custom.metrics.k8s.io/v1beta1 | jq -r . | grep cuda_test_gpu_avg
"name": "namespaces/cuda_test_gpu_avg",
"name": "deployments.apps/cuda_test_gpu_avg",

HPA

apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: cuda-test
  namespace: default
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: cuda-test
  minReplicas: 1
  maxReplicas: 3
  metrics:
  - type: Object
    object:
      describedObject:
        apiVersion: apps/v1
        kind: Deployment
        name: cuda-test
      metric:
        name: cuda_test_gpu_avg
      target:
        type: Value
        value: 2500

기준값 2500은 DCGM_FI_DEV_FB_USED 단위(MiB)다. GPU 메모리 사용량이 2500MiB를 넘으면 스케일 아웃한다.

부하 Deployment

gpu_burn이 메모리 약 5000MB를 쓰도록 실행해 HPA 기준을 넘긴다.

apiVersion: apps/v1
kind: Deployment
metadata:
  name: cuda-test
  labels:
    app: cuda-test
spec:
  selector:
    matchLabels:
      app: cuda-test
  template:
    metadata:
      labels:
        app: cuda-test
    spec:
      containers:
      - name: gpu-burn
        image: "oguzpastirmaci/gpu-burn"
        command: ["sh", "-c", "while true; do ./gpu_burn -m 5000 200; sleep 3000; done"]
        resources:
          limits:
            nvidia.com/mig-1g.5gb: 1

MIG 시험에서는 nvidia.com/mig-1g.5gb: 1을, Time-Slicing 시험에서는 nvidia.com/gpu: 1을 요청했다. MIG에서는 maxReplicas를 4로 올려서 시험했다.

4. 결과

HPA 이벤트에 Scaled up, Scaled down 기록이 남아 스케일 아웃과 인이 모두 동작하는 것을 확인했다.

MIG에서는 Pod가 1개에서 4개로 늘었고, nvidia-smi의 프로세스 표에서 GPU 인스턴스 ID 7, 9, 11, 12번이 Pod에 자동으로 하나씩 할당된 것을 볼 수 있었다. 부하가 줄자 남는 Pod가 종료되며 스케일 인이 이어졌다.

Time-Slicing(replicas: 3)에서도 같은 방식으로 Pod가 1개에서 3개로 늘었다가 줄었다.
