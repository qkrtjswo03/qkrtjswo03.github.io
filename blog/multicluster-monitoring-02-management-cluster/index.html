매니지먼트 차트에 올라가는 Grafana 12.2, Thanos Query/Store Gateway/Compactor, SeaweedFS S3, Prometheus Sidecar의 역할과 포트, Istio VirtualService 노출, 데이터소스와 대시보드 구성을 정리했다.

검증 조건

테스트 버전
  • Grafana 차트 8.6.4 (app 11.3.1), 이미지 12.2
  • Thanos 차트 15.13.0 (app 0.37.2), Sidecar v0.31.0
  • SeaweedFS 4.0.405 (app 4.05)
  • Alertmanager v0.27.0
  • Prometheus v3.5.0
환경
매니지먼트 클러스터, Istio Gateway 사전 구성, 네임스페이스 monitoring
검증 시점
2025년
핵심 결론
조회는 Grafana가 Istio VirtualService로 받고, 멀티클러스터 메트릭은 Thanos Query, 장기 블록은 SeaweedFS S3(내부 8333, NodePort 30333)와 Store Gateway가 담당한다.

앞 글의 전체 그림에서 매니지먼트 클러스터 쪽만 따라간다. 사용자는 여기 Grafana로 들어오고, Thanos Query가 여러 클러스터의 메트릭을 모으며, SeaweedFS가 Thanos 블록의 객체 스토어가 된다.

외부 접속: Grafana와 Istio

Grafana 이미지 태그는 12.2다. 하위 차트 버전은 8.6.4이고 차트의 appVersion은 11.3.1이라, 상위 values가 이미지 태그를 12.2로 덮어 쓰는 구성이다.

Istio Gateway는 차트가 만들지 않는다. 이미 있는 istio-system/<GATEWAY>에 VirtualService가 붙고, 호스트는 grafana.example.com, serve_from_sub_path: true다. 경로 예시는 /grafana(VirtualService는 :80으로 보낸다), Viewer는 /grafana/dashboards/, 관리자 로그인은 /grafana/login이다. grafana.ini.server의 domain과 root_url도 같은 호스트에 맞춘다. 관리자 비밀번호는 values의 adminPassword로 두고, 값은 <CHANGE_ME>로만 적는다.

Ingress로 Alertmanager / Prometheus / Thanos Query Frontend를 여는 항목은 기존 구성 values에서는 enabled: true(*.example.com, monitoring-tls)이고, 새 구성에서는 주석 처리되어 비활성이다. Grafana 조회 경로는 두 구성 모두 VirtualService를 쓴다.

Thanos와 Prometheus

매니지먼트 클러스터에도 Prometheus v3.5.0이 replicas 2로 뜨고, Thanos Sidecar(v0.31.0)가 붙는다. Alertmanager는 v0.27.0이다. kube-state-metrics v2.14.0, node-exporter v1.8.2, Prometheus Operator 이미지는 v0.80.1이다. kube-prometheus-stack 차트 66.4.0의 appVersion은 v0.78.2지만, 상위 values가 Operator 이미지를 v0.80.1로 지정한다.

매니지먼트 클러스터 Thanos 차트(15.13.0, app 0.37.2, 이미지 0.37.2-debian-12-r7)가 올리는 구성 요소는 다음과 같다.

구성 요소 역할
Query / Query Frontend 여러 store를 묶어 PromQL 조회. Grafana 데이터소스 thanos가 Query :9090을 가리킨다
Store Gateway SeaweedFS의 과거 TSDB 블록을 StoreAPI :10901로 제공한다
Compactor 업로드된 블록을 압축·보존한다. Bucket Web이 함께 붙는다
Sidecar (Prometheus 쪽) 매니지먼트 클러스터 로컬 Prometheus의 최신 데이터를 Query에 제공한다

Query stores에는 비즈니스 클러스터 Sidecar와 매니지먼트 클러스터 Store Gateway, 매니지먼트 클러스터 Sidecar가 함께 들어간다.

thanos:
  objstoreConfig: |-
    type: s3
    config:
      bucket: thanos
      endpoint: <MANAGEMENT-VIP>:30333
      access_key: <CHANGE_ME>
      secret_key: <CHANGE_ME>
      insecure: true
      signature_version2: true
  query:
    stores:
      - <BUSINESS-NodeIP>:10901
      - prometheus-stack-thanos-storegateway.monitoring.svc.cluster.local:10901
      - prometheus-stack-kube-prom-thanos-discovery:10901

objstoreConfig의 버킷·엔드포인트·키는 charts/seaweedfs/file/s3-key.yaml과 같아야 한다. 비즈니스 클러스터 Sidecar 주소가 바뀌면 매니지먼트 차트를 다시 적용한다. Thanos Query / Query Frontend / Store Gateway는 podAntiAffinityPreset: hard와 node=infra:NoSchedule 및 control-plane taint toleration을 쓴다.

최초 블록이 S3에 보이기까지 약 2시간이 걸릴 수 있다. Query의 Store UI에서 Sidecar(business1, management)가 보이는지, Grafana에서 데이터소스 thanos를 고르고 cluster 변수로 매니지먼트 클러스터와 비즈니스 클러스터가 모두 나오는지를 확인한다.

SeaweedFS S3

객체 스토어는 SeaweedFS 4.05, 차트 4.0.405다. allInOne으로 replicas 1, s3.enabled: true, PVC 64Gi, 단일 노드 라벨을 쓴다. 클러스터 내부 S3는 :8333, 클러스터 밖(비즈니스 클러스터 Sidecar 업로드, 운영 확인)은 NodePort 30333이다. Thanos 버킷 이름은 thanos다.

HA 모니터링 파드는 노드 라벨 example.io/monitoring-ha=true(infra 노드 2대), replicas=1인 파드는 example.io/monitoring-single=true(infra 노드 1대)를 쓴다. values 주석 기준 예시는 다음과 같다.

kubectl label node <node1> node=infra example.io/monitoring-ha=true
kubectl label node <node2> node=infra example.io/monitoring-ha=true
kubectl label node <node3> node=infra example.io/monitoring-single=true

데이터소스와 대시보드

데이터소스는 매니지먼트 클러스터 Grafana의 Connections → Data sources에서 확인하고, 저장 뒤 새로고침해 대시보드 Import 상태를 본다.

이름 유형 URL 비고
prometheus Prometheus http://prometheus-stack-kube-prom-prometheus.monitoring.svc.cluster.local:9090 매니지먼트 클러스터 직접 조회
thanos Prometheus http://prometheus-stack-thanos-query.monitoring.svc.cluster.local:9090 멀티클러스터 조회
loki Loki http://<VIP 또는 NodeIP>:<Loki-Gateway-NodePort> 비즈니스 클러스터 Loki Gateway, VIP 권장
virt-prometheus Prometheus https://<OpenStack-VIP>:9090 또는 Thanos :11909 가상화, Skip TLS
virt-loki Loki https://<OpenStack-VIP>:13100 가상화, Skip TLS

대시보드 JSON은 Grafana 하위 차트 dashboards/에 있고, 플랫폼 폴더와 가상화 폴더로 프로비저닝된다. 기본 시간대는 Asia/Seoul이다. 언어는 설치 도우미에서 ko(기본) 또는 en을 고른다. 구성은 같고, en을 고르면 각 폴더의 en/*.json을 쓴다.

플랫폼 대시보드는 8종이다. CNI Cilium, Components, ETCD, Host GPU, Logs, Node, Service, Volume. ETCD와 Host GPU JSON에는 샘플 IP 자리표시자가 들어 있다. Service 대시보드는 namespace를 선택해야 패널이 채워진다. 가상화 대시보드는 OpenStack/베어메탈용 12종(Cluster Monitoring, GPU, HAProxy & Pacemaker, Log, Memcached, 종합 Monitoring, MySQL, Node IPMI, Node Resource, RabbitMQ, Virtual Machine Resource, Virtual Network)이다.
